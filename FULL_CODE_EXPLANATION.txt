2. index.html — THE ENTRY POINT
=============================================================================
File: /index.html

```html
<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>
```

Line-by-line:
→ `<div id="root">` — This is the single HTML element that React controls.
   When React starts, it completely takes over this div and renders everything inside it.
→ `<script type="module">` — Tells the browser this is a modern ES Module.
   Vite (our build tool) processes this and injects our React bundle here.

If a jury member asks: "Why is there almost no HTML?"
Answer: "That's the beauty of React. It's a Single Page Application (SPA). 
The HTML file is just the shell. React generates all the UI dynamically in JavaScript."

=============================================================================
File: /src/App.jsx

```javascript
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom';
import AdminLayout from './components/layout/AdminLayout';
import Dashboard from './pages/Dashboard';
import Users from './pages/Users';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/admin" element={<AdminLayout />}>
          <Route index element={<Navigate to="dashboard" />} />
          <Route path="dashboard" element={<Dashboard />} />
          <Route path="users" element={<Users />} />
          <Route path="customers" element={<Customers />} />
          // ... 14 more routes
        </Route>
      </Routes>
    </BrowserRouter>
  );

```

Line-by-line:
→ `<BrowserRouter>` — Wraps the entire app and enables URL-based navigation (e.g., /admin/customers).
   It listens to the browser's history API so the URL changes without reloading the page.
→ `<Route path="/admin" element={<AdminLayout />}>` — This is a PARENT route.
   AdminLayout renders the persistent sidebar and header. Any child routes render INSIDE it.
→ `<Route index element={<Navigate to="dashboard" />} />` — When someone visits just "/admin",
   this automatically redirects them to "/admin/dashboard". It's like a default homepage.
→ `<Route path="customers" element={<Customers />} />` — When the URL is "/admin/customers",
   React renders the Customers component inside the AdminLayout.

If a jury asks: "How does clicking the sidebar link load a new page?"
Answer: "React Router intercepts the click, changes the URL, and renders the matching 
component — all without any network request. It's instantaneous."

5. storageService.js — THE MOCK DATABASE LAYER
=============================================================================
File: /src/services/storageService.js

This is the most architecturally important file. It replaces a backend API.

```javascript
export const getFromStorage = (key, defaultVal = []) => {
  try {
    const item = localStorage.getItem(key);
    return item ? JSON.parse(item) : defaultVal;
  } catch {
    return defaultVal;
  }
};
```
→ `localStorage.getItem(key)` — Reads a string from the browser's persistent storage.
   LocalStorage is like a mini key-value database built into every browser.
→ `JSON.parse(item)` — Our data is stored as a JSON string. This converts it back to a 
   JavaScript object/array so we can work with it in React.
→ `try/catch` — If the JSON is corrupted or the key doesn't exist, we return the defaultVal
   instead of crashing the app. This is defensive programming.

```javascript
export const initializeData = () => {
  if (!localStorage.getItem('df_users')) {
    setToStorage('df_users', initialUsers);
  }
  // ... same check for all 17 data types
};
```
→ `if (!localStorage.getItem('df_users'))` — This check is CRITICAL. It only seeds mock data 
   the VERY FIRST TIME the app loads. On every subsequent visit, real data is used.
   This is why data persists across browser refreshes.

```javascript
export const saveEntity = (key, entity, isNew = false) => {
  const all = getFromStorage(key, []);
  let updated;
  if (isNew) {
    updated = [...all, entity];       // ADD: spread existing, append new
  } else {
    updated = all.map(e =>            // UPDATE: map over all, replace matching id
      e.id === entity.id ? entity : e
    );
  }
  setToStorage(key, updated);
  return updated;
};
```
→ `const all = getFromStorage(key, [])` — First, load the entire current array from storage.
→ `isNew` — A boolean flag that controls whether we're CREATING or UPDATING.
→ `[...all, entity]` — The spread operator (`...`) copies all existing items into a new array,
   then appends the new entity at the end. We never mutate the original array.
→ `all.map(e => e.id === entity.id ? entity : e)` — This is how we UPDATE a record without
   a real database. We loop through every item. If the ID matches, we replace it.
   If not, we keep it unchanged. This returns a brand new array.
→ `return updated` — We return the new array so React components can immediately update 
   their state with fresh data.

```javascript
export const deleteEntity = (key, id) => {
  const all = getFromStorage(key, []);
  const updated = all.filter(e => e.id !== id);  // REMOVE: keep everything EXCEPT the deleted id
  setToStorage(key, updated);
  return updated;
};
```
→ `all.filter(e => e.id !== id)` — The JavaScript `.filter()` method creates a new array
   containing only items where the condition is TRUE. By saying "id must NOT equal the
   deleted id", we effectively remove that one record from the array.

7. downloadHelper.js — CLIENT-SIDE FILE EXPORT
=============================================================================
File: /src/services/downloadHelper.js

```javascript
export const downloadCSV = (dataArray, filename) => {
  if (!dataArray || !dataArray.length) {
    alert("No data to download!");
    return;
  }

  const headers = Object.keys(dataArray[0]).join(',');
  const rows = dataArray.map(obj => Object.values(obj).join(',')).join('\n');
  const csvContent = `${headers}\n${rows}`;

  const blob = new Blob([csvContent], { type: 'text/csv;charset=utf-8;' });
  const url = URL.createObjectURL(blob);

  const link = document.createElement('a');
  link.setAttribute('href', url);
  link.setAttribute('download', `${filename}.csv`);
  link.style.visibility = 'hidden';
  document.body.appendChild(link);
  link.click();
  document.body.removeChild(link);
};
```

Line-by-line:
→ `Object.keys(dataArray[0]).join(',')` — Takes the first object's keys (e.g., "id,name,email")
   and joins them with commas to create the CSV header row.
→ `dataArray.map(obj => Object.values(obj).join(','))` — For each object, extract all the 
   values and join them with commas to create one CSV data row per record.
→ `new Blob([csvContent], { type: 'text/csv' })` — A Blob (Binary Large Object) is a raw
   file stored in memory. We're packaging our CSV string as a real file object.
→ `URL.createObjectURL(blob)` — Creates a temporary URL that points to the in-memory Blob.
   This URL looks like: "blob:http://localhost:5173/some-unique-id"
→ `document.createElement('a')` — We create an invisible <a> tag in the DOM.
→ `link.setAttribute('download', filename)` — The `download` attribute tells the browser:
   "When this link is clicked, download the file instead of navigating to it."
→ `link.click()` — We programmatically click the invisible link. The browser sees the 
   `download` attribute and instantly saves the file to the user's Downloads folder.
→ `document.body.removeChild(link)` — Clean up the invisible link from the DOM.

8. AdminLayout.jsx — THE SHELL
=============================================================================
File: /src/components/layout/AdminLayout.jsx

```javascript
function AdminLayout() {
  const [collapsed, setCollapsed] = useState(false);
  const location = useLocation();
  const navigate = useNavigate();

  return (
    <div className={`admin-layout ${collapsed ? 'sidebar-collapsed' : ''}`}>
      <aside className={`sidebar ${collapsed ? 'collapsed' : ''}`}>
        <button onClick={() => setCollapsed(!collapsed)}>
          {collapsed ? '→' : '←'}
        </button>
        {navItems.map(item => (
          <NavLink to={item.path} className={({ isActive }) => isActive ? 'active' : ''}>
            {item.label}
          </NavLink>
        ))}
      </aside>

      <main className="main-content">
        <Outlet />
      </main>
    </div>
  );
}
```
→ `const [collapsed, setCollapsed] = useState(false)` — A single boolean state variable
   controls whether the sidebar is wide (false) or narrow (true).
→ `` `admin-layout ${collapsed ? 'sidebar-collapsed' : ''}` `` — We dynamically inject a
   CSS class based on state. When `collapsed` is true, the CSS class `sidebar-collapsed`
   is added, which triggers a CSS rule that shrinks the sidebar width.
→ `useLocation()` — A React Router hook that gives us the current URL path. We use this
   to determine which sidebar link should be highlighted as "active".
→ `({ isActive }) => isActive ? 'active' : ''` — React Router's NavLink automatically 
   passes `isActive` — a boolean that's true when the link's path matches the current URL.
→ `<Outlet />` — This is the most important line. It's a React Router placeholder that says:
   "Render whatever child route matches the current URL here." This is what loads 
   Dashboard, Customers, Products, etc. inside the same layout without re-rendering the sidebar.

9. UI.jsx — THE CUSTOM DESIGN SYSTEM
=============================================================================
File: /src/components/common/UI.jsx

Instead of using Material UI or Ant Design, we built our own component library.

--- BUTTON ---
```javascript
export const Button = ({ children, variant = 'primary', className = '', ...props }) => (
  <button className={`btn btn-${variant} ${className}`} {...props}>
    {children}
  </button>
);
```
→ `variant = 'primary'` — Default value. If no variant is passed, it defaults to primary.
→ `className={`btn btn-${variant}`}` — Dynamically builds the CSS class name.
   A `variant="danger"` call becomes class `btn btn-danger` which maps to red styling in CSS.
→ `{...props}` — The spread operator passes ALL other props (like onClick, disabled, type)
   directly to the underlying HTML button. This makes the component infinitely flexible
   without us having to manually list every possible prop.

--- MODAL ---
```javascript
export const Modal = ({ isOpen, onClose, title, children, footer }) => {
  if (!isOpen) return null;
  return (
    <div className="modal-overlay">
      <div className="modal-content">
        <div className="modal-header">
          <h3>{title}</h3>
          <button onClick={onClose}>&times;</button>
        </div>
        <div className="modal-body">{children}</div>
        {footer && <div className="modal-footer">{footer}</div>}
      </div>
    </div>
  );
};
```
→ `if (!isOpen) return null` — When the modal is closed, React renders NOTHING to the DOM.
   This is called "conditional rendering" and is far more efficient than just hiding it with CSS.
→ `{children}` — Whatever JSX we put between <Modal>...</Modal> tags is injected here.
   This pattern is called "composition" and makes the Modal reusable across all 17 pages
   without any special props for each page's unique form content.
→ `{footer && <div>...</div>}` — The footer is optional. If no footer prop is passed,
   the `&&` short-circuit means nothing is rendered for the footer section.

--- DATATABLE (most complex component) ---
```javascript
export const DataTable = ({ columns, data, loading, emptyMessage, emptyAction }) => {
  const [sortConfig, setSortConfig] = useState({ key: null, direction: 'asc' });
  const [currentPage, setCurrentPage] = useState(1);
  const itemsPerPage = 10;

  const sortedData = React.useMemo(() => {
    let sortableItems = [...data];
    if (sortConfig.key !== null) {
      sortableItems.sort((a, b) => {
        if (a[sortConfig.key] < b[sortConfig.key]) return sortConfig.direction === 'asc' ? -1 : 1;
        if (a[sortConfig.key] > b[sortConfig.key]) return sortConfig.direction === 'asc' ? 1 : -1;
        return 0;
      });
    }
    return sortableItems;
  }, [data, sortConfig]);

  const totalPages = Math.ceil(sortedData.length / itemsPerPage);
  const currentData = sortedData.slice(
    (currentPage - 1) * itemsPerPage,
    currentPage * itemsPerPage
  );
```
→ `sortConfig` state — Stores which column to sort by and in which direction (asc/desc).
→ `React.useMemo(...)` — This is a performance optimization. The sort function only 
   re-runs when `data` or `sortConfig` changes. It does NOT re-run on every render.
   This keeps the table fast even with 1000+ rows.
→ `[...data]` — We spread the data array into a NEW array before sorting. We never mutate
   the original prop. This is a core React principle: immutable state updates.
→ `sortableItems.sort((a, b) => ...)` — JavaScript's native sort. The comparator returns:
   -1 to put 'a' first, 1 to put 'b' first, 0 if equal.
→ `Math.ceil(sortedData.length / itemsPerPage)` — Calculates total pages. For 25 records
   with 10 per page: Math.ceil(25 / 10) = Math.ceil(2.5) = 3 pages.
→ `sortedData.slice((currentPage - 1) * itemsPerPage, currentPage * itemsPerPage)` —
   Extracts only the current page's records. Page 2 with 10 per page: slice(10, 20).

const chartData = [

const [hoveredBar, setHoveredBar] = useState(null);

→ `hoveredBar` state — Tracks which bar index the mouse is over (null = none).

```javascript
{chartData.map((data, i) => (
  <div
    key={i}
    onMouseEnter={() => setHoveredBar(i)}
    onMouseLeave={() => setHoveredBar(null)}
    style={{
      height: `${data.height}%`,
      background: hoveredBar === i
        ? 'var(--primary)'
        : 'linear-gradient(180deg, var(--primary) 0%, rgba(79,70,229,0.2) 100%)',
    }}
  >
    {hoveredBar === i && (
      <div style={{ position: 'absolute', top: '-40px' }}>
        ${data.revenue.toLocaleString()}
      </div>
    )}
  </div>
))}
```
→ `.map((data, i) =>` — Creates one bar div for EACH month in chartData automatically.
   If we add December to the array, a 12th bar appears with zero code changes.
→ `onMouseEnter={() => setHoveredBar(i)}` — When mouse enters bar #3, state becomes 3.
→ `hoveredBar === i ? 'var(--primary)' : 'linear-gradient...'` — Ternary operator.
   "If this bar is the hovered one, solid indigo. Otherwise, gradient."
→ `{hoveredBar === i && (...)}` — Conditional rendering. The tooltip div only exists in 
   the DOM when this specific bar is hovered. No CSS display:none tricks needed.
→ `data.revenue.toLocaleString()` — JavaScript built-in that formats 42500 as "42,500".

11. Customers.jsx — FULL CRUD WALKTHROUGH (DEMO THIS ONE)
=============================================================================
File: /src/pages/Customers.jsx

This is the most complete example of our CRUD pattern. Show this file to the jury.

```javascript
const [customers, setCustomers] = useState(() => getCustomers());
```
→ `() => getCustomers()` — This is a "lazy initializer". The function is only called ONCE
   when the component first mounts. It reads from LocalStorage. If we wrote 
   `useState(getCustomers())` instead, it would call LocalStorage on EVERY render — slow!

```javascript
const [modalItem, setModalItem] = useState(null);
```
→ `null` means the modal is closed. When we set modalItem to an object, the modal opens.
   The SAME state variable serves double duty: null=closed, object=open+data.

```javascript
const handleOpenAdd = () => {
  setModalItem({
    name: '',
    company: '',
    email: '',
    tier: 'Standard',
    creditLimit: 0,
    status: 'Active'
  });
};
```
→ We set modalItem to a BLANK object (no id field). The modal sees this and renders 
   an empty form. When saved, the absence of an `id` tells `saveEntity` to CREATE.

```javascript
const handleOpenEdit = (customer) => {
  setModalItem({ ...customer });
};
```
→ `{ ...customer }` — Spread creates a COPY of the customer object. This is critical.
   If we passed the original object directly and the user edited the form, the original
   data would be mutated before saving — causing bugs. The copy prevents this.

```javascript
const handleSaveModal = () => {
  if (!modalItem.name || !modalItem.company) {
    toast.error("Name and Company are required.");
    return;
  }
  const isNew = !modalItem.id;
  const entityToSave = isNew ? { ...modalItem, id: 'c_' + Date.now() } : modalItem;
  const updated = saveEntity('df_customers', entityToSave, isNew);
  setCustomers(updated);
  toast.success(`Customer ${isNew ? 'added' : 'updated'} successfully!`);
  setModalItem(null);
};
```
→ `!modalItem.name` — Validation. If name is empty string (falsy), show an error and stop.
   The `return` prevents execution from continuing.
→ `const isNew = !modalItem.id` — If there's no id, it's a new record. The `!` (NOT) 
   operator converts: undefined → true (it IS new), 'c_123' → false (it's an update).
→ `{ ...modalItem, id: 'c_' + Date.now() }` — Generate a unique ID using the current 
   timestamp in milliseconds. Date.now() returns something like 1725517800000 — effectively
   unique since two records can't be saved at the exact same millisecond.
→ `setCustomers(updated)` — React sees the state has changed and re-renders the component.
   The DataTable automatically shows the new/updated record without any extra code.
→ `setModalItem(null)` — Resets state to null, which closes the modal.

```javascript
const filtered = customers.filter(c => {
  const s = search.toLowerCase();
  return (c.name || '').toLowerCase().includes(s) ||
         (c.company || '').toLowerCase().includes(s) ||
         (c.email || '').toLowerCase().includes(s);
});
```
→ `(c.name || '')` — DEFENSIVE PROGRAMMING. If `c.name` is undefined or null, 
   use empty string instead. Without this, `.toLowerCase()` would throw a TypeError
   and crash the entire app. This is a professional-grade safety pattern.
→ The `filtered` variable is computed fresh on every render. When the user types in the
   search box, React re-renders, `filtered` is recalculated, and the table updates instantly.
   No extra state, no useEffect needed — just pure computation.

SUMMARY FOR JURY PRESENTATION:
=============================================================================

KEY TECHNICAL DECISIONS TO HIGHLIGHT:

1. NO BACKEND — Used LocalStorage with a custom service layer (storageService.js)
   as a perfect mock database. Fully replace-able with a real REST API in Phase 2.

2. NO UI LIBRARIES — Built Button, Modal, DataTable, Badge, Select from scratch in UI.jsx.
   Proves deep understanding of React component composition and CSS.

3. IMMUTABLE STATE — Never mutate arrays or objects directly. Always use .map(), 
   .filter(), spread (...), and new object creation. This is the React way.

4. DEFENSIVE PROGRAMMING — Every data access uses `(value || '')` and `(value || 0)` 
   fallbacks to prevent crashes on missing or null data.

5. PERFORMANCE — useMemo for expensive sorting, lazy useState initializers for storage reads.

6. DESIGN SYSTEM — CSS custom properties (variables) for a fully themeable, consistent UI.
